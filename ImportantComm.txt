4. UNDERSTAND PUSH, FETCH AND PULL: https://youtu.be/mAFoROnOfHs?t=3360
PUSH: Sending local changes to REMOTE repository
FETCH: Download changes into local repository, but not yet merging yet. In local memory. Won't appear in local directory yet.
PULL : Pull = FETCH + MERGE
      This allows us to VIEW the remote changes
      Fetching plus merging -so your working depository immediately reflects the remote changes. 
To push changes to REMOTE
git push origin main
- Origin refers to remote rep. Main is branch you want to push.
- Other branches will not be uploaded
- IN github select main then branches
To upload other branches
 1. switch branches: git checkout <NAME>
 2. push: git push origin <NAME>
Git Fetch vs Pull
Fetch
-First get changes from remote: git fetch
-Then merge those changes: git merge
Pull
git pull: This combines merge and fetch

Discarding local changes
- Done when code a lot locally but not work.
- Could manually fix line by line but too long
git restore <FILENAME>
git restore services:  This restores an entire directory(folder) instead of single file
git restore . : This restores an entire repository
git restore --staged <filename> : This restores file but removes staging area

Git Stash: Saving unfinished work
Why use it 
-When work on 1 branch, asked to check another branch
-Git doesn't allow switching branches without being committed(saved)
Steps
- Store changes: git stash
- switch branches 
- go back to main branch 
- get changes back up: git stash pop
                       get stash pop stash@<ID>
                       -After stash is used, removed PERMA
-If stashed multiple times, get them them in order by recent
git stash apply: This applies stashed changes but keeps them in STASH LIST.
git stash list: This lists all stashs
- This gets all the stashes with their IDS
git stash pop stash @{0}
git stash apply stash @{0}
git stash drop: drops all stored stash

Git revert: Undoing commits Safely 
What is it
- Used to undo the changes made in a previous commit.
- Instead of deleting old commit, creates new one that reverses changes.
Command: git revert <ID>
- ID obtained by git log --oneline
- enter ":wq" : This means write and quit 
- After which changes would be undone
Reset vs Revert 
- Reset takes work back to previous pint then discards previous work withour creating new commits
- Revert: Removes changes from a commit and makes a new one
- If on GitHub, you check logs after reset, no record of removed commits

Git Rebase: Cleaning up history
Why 
- When you want to add something from another branch(merge), it creates a commit
- Doing this multiple times can make commit history long
Process
- git first identify most recent common commit between current branche and rebasing one
- All commits in your branch after shared point stored aside
- Git puts all the features in main branch into feature(current) branch
- Then the current features you have are added on end 
- Do changes on one branch 
- Don't use it when multiple devs use it
Command
git rebase main:
